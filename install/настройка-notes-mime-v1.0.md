# Настройка Notes: хранить почту в формате отправителя (MIME)

## Зачем

Уведомления 1С:ДО приходят как интернет-почта с HTML-ссылкой вида:

```
e1c://server/b-erp-appp03/do#e1cib/data/Задача.ЗадачаИсполнителя?ref=814e005056b663c811f1a5def50f01e6
```

При настройке Notes «хранить в формате Notes rich text» конвертация HTML→RichText
разбивает ссылку: значение параметра `?ref=<…>` отбрасывается, и дашборд получает
адрес, обрезанный на `?ref`. Диагностика 08.09.2026 показала: в таком письме
значения нет ни в тексте, ни в MIME (часть не сохранена), ни в DXL — восстановить его нельзя.

При хранении в формате отправителя (MIME) исходный HTML сохраняется целиком,
и [`_urls_from_mime()`](../notes_gemini.py) находит полный адрес с ненулевым `?ref`.

## Шаги (клиент HCL Notes 14)

1. Меню **File → Preferences** (Файл → Параметры).
2. Раздел **Mail → Internet** (Почта → Интернет).
3. В блоке **Internet mail format**:
   - пункт **«When receiving unencrypted mail»** переключите на **«Keep in senders' format»**
     (по-русски: «При получении незашифрованных сообщений» → «Хранить в формате отправителя»);
   - если вместо выбора стоит галочка «store in Notes rich text format» — снимите её.
4. Нажмите **OK**.

Действует только на **новые** письма, полученные после изменения настройки.
Для уже полученных писем значение `?ref` восстановить невозможно.

## Проверка

1. Дождитесь нового уведомления от 1С:ДО («Задача …», «Ссылка на задачу 1С:ДО: …»).
2. Из корня проекта выполните:

```cmd
py tools/probe_do_links.py
```

3. В выводе для этого письма должна появиться строка `URL из MIME` с полным адресом
   `e1c://…?ref=<значение>`, а `do_url итог` — с ненулевым значением параметра.
